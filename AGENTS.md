# AGENTS.md - Developer & Agent Guide for `mikrotik-api-rs`

This document serves as the primary technical reference for AI agents and human contributors working on the `mikrotik-api-rs` codebase. It outlines the project's architecture, protocol intricacies, development conventions, known traps, and technical debt.

---

## 1. Project Overview

`mikrotik-api-rs` provides an asynchronous Rust client library (`mikrotik_api`) and a command-line interface tool (`mk-client`) to interact with MikroTik RouterOS devices via their native, proprietary binary-text API (conventionally exposed on TCP port 8728 for plaintext, and port 8729 for SSL/TLS).

### Key Characteristics
- **Language / Edition**: Rust (2021 edition).
- **Async Runtime**: `tokio` (v1.x) with full features (TCP networking, channels, synchronization).
- **Serialization**: Custom `serde` deserializer (`SentenceDeserializer`) mapping RouterOS sentence replies directly into typed Rust structs/enums.
- **Protocol Nature**: Full-duplex multiplexed sentence protocol using tag identifiers (`.tag=<u16>`).

## 3. RouterOS API Protocol Internals

MikroTik RouterOS uses an asynchronous, multiplexed protocol consisting of **words** and **sentences**.

### 3.1 Word Length Encoding
Every word is prefixed by its length encoded in 1 to 5 bytes:
- `len <= 0x7F` (0..127): 1 byte (`len as u8`).
- `len <= 0x3FFF` (128..16383): 2 bytes (`len | 0x8000`, Big-Endian).
- `len <= 0x1FFFFF` (16384..2097151): 3 bytes (`len | 0xC00000`, Big-Endian, 3 bytes).
- `len <= 0xFFFFFFF`: 4 bytes (`len | 0xE0000000`, Big-Endian).
- `len >= 0x10000000`: 5 bytes (literal byte `0xF0` followed by 4-byte Big-Endian length).

Following the length bytes, the word's raw UTF-8 string bytes are sent.

### 3.2 Sentences
- A sentence is an array of words terminated by a zero-length word (`0x00`).
- The **first word** of a request is the command path (e.g., `/system/identity/print`, `/interface/listen`, `/login`).
- Subsequent words are attributes formatted according to their prefix:
  - `?`: Query filter words (e.g., `?running=true`, `?#|`).
  - `.` or `=`: Direct attributes or proplists (e.g., `.proplist=name,running`, `.tag=123`).
  - Plain names: Prepended with `=` (e.g., `name` with value `admin` becomes `=name=admin`).

### 3.3 Response Framing & Multiplexing
The router responds with sentences containing control words:
- `!re`: Reply frame containing data words (e.g., `=name=ether1`, `=running=true`).
- `!done`: Indicates completion of a command or end of a stream.
- `!trap`: Indicates an error, accompanied by `=message=...` and optionally `=category=...`.
- `!fatal`: Severe protocol or daemon error; router will immediately terminate the connection.

Each reply contains `.tag=<id>`, corresponding to the request tag generated by the client. This allows multiple commands and streaming listeners to run concurrently over a single TCP stream.

## 4. Architecture & Key Patterns

### 4.1 Typestate Pattern: Connection Lifecycle
The connection transitions through compile-time enforced states:
- `mikrotik_api::connect(addr)` &rarr; `MikrotikAPI<Disconnected>` (plaintext, port 8728)
- `mikrotik_api::connect_tls(addr, domain)` &rarr; `MikrotikAPI<Disconnected>` (TLS, port 8729)
- `mikrotik_api::connect_tls_with_config(addr, domain, config)` &rarr; `MikrotikAPI<Disconnected>` (custom TLS config)
- `MikrotikAPI::from_stream(stream)` / `from_parts(reader, writer)` &rarr; `MikrotikAPI<Disconnected>` (arbitrary duplex async transport)
- `api.authenticate(login, password)` &rarr; `Result<MikrotikAPI<Authenticated>, Error>`
- Only `MikrotikAPI<Authenticated>` exposes query, listener, and execution methods.

```rust
let disconnected = mikrotik_api::connect_tls("192.168.88.1:8729", "192.168.88.1").await?;
let mut api = disconnected.authenticate("admin", "password").await?;
let resources = api.system_resources().await?;
```

### 4.2 Multiplexing & Background Event Loop
- `MikrotikAPI` decouples the underlying transport using a shared `Arc<MikrotikInner>` holding `tokio::sync::Mutex<BufWriter<Box<dyn AsyncWrite + Send + Unpin>>>` and spawns a background Tokio reader task:
  - Reader (`R: AsyncRead + Send + Unpin + 'static`): Handed off to a background Tokio task (`event_loop` in `src/api/listener.rs`).
  - Writer: Wrapped in `tokio::sync::Mutex<BufWriter<Box<dyn AsyncWrite + Send + Unpin>>>` inside `MikrotikInner`. Lock is acquired exclusively during `send_command` and dropped immediately after write/flush.
- Shared State: `SharedTagMap` (`Arc<Mutex<TagMap>>`), `AtomicU16` for tag allocation, and async writer mutex are encapsulated in `Arc<MikrotikInner>`. `MikrotikAPI<Authenticated>` derives `Clone` (creating a shallow handle) and methods take `&self`, allowing concurrent multiplexing via `tokio::join!` or sharing across Tokio tasks.
- For each request:
  1. An incremental tag `u16` (1..=65534) is generated via `AtomicU16` with wrap-around, guaranteeing no collision with active keys in `tag_map`.
  2. The call handler is registered into `tag_map`.
  3. The request is transmitted with `.tag=<tag_id>`.
  4. The background `event_loop` reads sentences, parses `.tag`, and calls `push_reply()` or `done()` on the registered handler.

### 4.3 Async Call Abstractions (`src/api/call/`)
- `OneShotCall<T>`: Implements `Future<Output = Response<T>>`. Used for single-reply commands like `/system/resource/print`.
- `ArrayListCall<T>`: Implements `Future<Output = Vec<Response<T>>>`. Collects multiple `!re` replies into a `Vec` until `!done`.
- `StreamingCall<T>`: Implements `futures::Stream<Item = Response<T>>`. Powered by an unbounded Tokio `mpsc` channel. Emits items as `!re` arrives; returns `None` on `!done`.
- `EmptyCall`: Type alias for `OneShotCall<()>`. Used for `/login` and `/cancel`.

### 4.4 Serde Deserialization Pipeline (`src/api/de/`)
- `SentenceDeserializer<'de>` is a custom `serde::Deserializer` that walks a slice of sentence strings (`&[String]`).
- Converts sentence headers (`!re`, `!done`, `!trap`) into the `Response<T>` enum variants.
- Extracts key-value pairs (`=key=value`) into struct fields or map entries, safely preserving any `=` characters within attribute values.
- Automatically ignores `.tag` words during field decoding.

## 6. Critical Gotchas, Known Bugs & Technical Debt

When editing or extending this codebase, pay close attention to these known issues:

### 1. [RESOLVED in #1] `encode_len` Buffer Panics and Endianness Bug (`src/api/mod.rs`)
Previously, `res.copy_from_slice(...)` was called on empty `vec![]` (causing panics for `len >= 128`), and `to_ne_bytes()` / incorrect 3-byte slicing corrupted wire framing. This was resolved with `encode_len_usize`, `extend_from_slice`, `to_be_bytes()`, and correct Big-Endian slicing.


### 2. [RESOLVED in #2] CPU Spin in `Future::poll` (`src/api/call/one_shot.rs` & `src/api/call/array.rs`)
Previously, `cx.waker().wake_by_ref()` was called unconditionally inside `poll()`, causing Tokio worker threads to busy-spin at 100% CPU while waiting for a reply. This was resolved by storing `Option<Waker>` in `InnerCall` (`register_waker`) and waking it only when `done()` is triggered.


### 3. [RESOLVED in #5] Tag Map Memory Leak
Previously, completed calls were never removed from `SharedTagMap` in `event_loop` on `!done`, causing unbounded memory growth and eventually exhausting the `u16` tag space. This was resolved by removing tags from `SharedTagMap` upon receiving `FrameType::Done` in `event_loop`, and adding tag exhaustion protection with deterministic linear scan fallback in `next_tag`.

### 4. [RESOLVED] Failing Doctests in `src/lib.rs`
The code blocks in `src/lib.rs` documentation were updated with valid imports and async runners, verified by `cargo test --doc`.

### 5. Dead / Abandoned Files
- `src/api/blocking/de.rs`: Not exposed or used anywhere in the codebase. Contains leftover debugging prints (`println!("prout")`). Do not import or modify.
- `src/api/de/mod.rs`: Contains an unused `SeqVisitor` struct triggering compiler warnings.

### 6. Strict Compiler Enforcements
- `src/lib.rs` contains `#![deny(missing_docs)]`. Any new `pub` function, struct, enum, or field exported by the library **must** have documentation comments, or `cargo build` will fail.

### 7. Cargo.toml Typos & Leftovers
- `Cargo.toml` uses `keyword = [...]` instead of `keywords = [...]` (triggers Cargo warning).
- `md5` and `hex` dependencies are declared in `Cargo.toml` but never used in `src/`. (Likely planned for legacy pre-6.43 RouterOS MD5 challenge-response authentication).

### 8. [RESOLVED in #7] Panics on Untagged Frames and Non-Second .tag Position (`src/api/listener.rs`)
Previously, `event_loop` assumed `.tag` was strictly the second word in every sentence, using `tag.split_at(5)` and `id.parse().unwrap()`. Untagged `!done` caused an out-of-bounds panic on `"".split_at(5)`, frames where attributes preceded `.tag` were dropped, and malformed tags caused panics. This was resolved by scanning all sentence words with `strip_prefix(".tag=")`, parsing `u16` fallibly, handling `!fatal` independently, and ignoring untagged or malformed frames without crashing.

### 9. [RESOLVED in #10] Deserialization Failures on Unexpected Fields, >=4GiB Memory, and Version-Dependent Models
Previously, `SystemResources` defined memory/HDD fields as `u32`, which overflowed on routers with $\ge 4\text{ GiB}$ RAM (`total-memory=4294967296`), and required `factory-software` which CHR/x86 omit. Additionally, `Interface` declared non-optional fields (`actual_mtu`, FastPath counters `fp_*`, `tx_queue_drop`, `link_downs`) that are omitted on virtual/tunnel interfaces or platforms without FastPath, and `InterfaceMTU::Value` / `actual_mtu` were typed as `u16` which overflowed on loopback interfaces (`lo` with `65536` MTU). Furthermore, RouterOS 7 uses `last-link-up-time` instead of `last-link-up`. This was resolved by widening memory/HDD fields to `u64`, MTUs to `u32`, marking platform/interface-dependent fields as `Option<T>` with `#[serde(default)]`, adding alias `last-link-up-time`, and ensuring `deserialize_ignored_any` completely clears word/key/value state.

### 10. [RESOLVED in #30] Missing Public Re-Exports for Error, DeserializerError, and TrapCategory (`src/lib.rs`)
Previously, `Error`, `DeserializerError`, and `TrapCategory` were defined in private submodules without being re-exported in `src/lib.rs`, preventing downstream callers from naming `mikrotik_api::Error` or matching on `TrapCategory` and `Error` variants. This was resolved by re-exporting all three types at the crate root in `src/lib.rs` and adding complete doc comments to satisfy `#![deny(missing_docs)]`.

### 11. [RESOLVED in #29] SentenceDeserializer Panics on Signed Integers, Floats, u128, char, newtype_struct, !fatal, and Field Enums (`src/api/de/mod.rs`)
Previously, `SentenceDeserializer` forwarded signed integers, floats, `u128`, `char`, `unit_struct`, and `newtype_struct` to `deserialize_any`, which called `unimplemented!()`. Additionally, `!fatal` routed to `EnumVisitor`, whose `unit_variant` called `todo!()`. Furthermore, `deserialize_enum` unconditionally called `self.read_word()`, which consumed subsequent sentence words instead of using `self.current_value` / `self.current_key` when deserializing derived enums used as struct fields or map keys. This was resolved by implementing `parse_primitive` and explicit deserializers for all integer/float/char/newtype types, delegating `deserialize_any` to `deserialize_str`, routing `!fatal` to `"Fatal".into_deserializer()` while returning `Ok(())` from `EnumVisitor::unit_variant`, and consuming `current_value` / `current_key` in `deserialize_enum` before reading new words.

### 12. [RESOLVED in #31] Code Quality, Safety, CLI Ergonomics & Documentation Cleanup
Previously, `TrapCategory::deserialize` used `unsafe { core::mem::transmute(category) }`, triggering Clippy warnings. Clippy also warned on needless borrows and unused lifetimes in `src/api/mod.rs`. `encode_len_usize` silently truncated lengths > 4GiB on 64-bit systems. `mk-client` had typos (`mutualy exculisve`, `ressources`) and used raw `unwrap()` calls on connection/authentication/request failures. Documentation incorrectly referred to `/interfaces/print` and binary name `client`. These were resolved by using a safe `match` for `TrapCategory`, resolving Clippy warnings, asserting `len <= u32::MAX as usize` in `encode_len_usize`, adding proper error handling in `mk-client`, fixing documentation command paths and binary names, and adding `.DS_Store` to `.gitignore`.

### 13. [RESOLVED in #25] Connection Termination on Deserialization Failure and Masking as EndOfStream
Previously, when `deserialize_sentence` failed inside `OneShotCall::push_reply`, `ArrayListCall::push_reply`, or `StreamingCall::push_reply` (e.g., from a user struct schema mismatch), `caller.push_reply` returned `Err(CallError::BadSentence(e))`, causing `event_loop` to log an error and execute `break;`. This disconnected every in-flight caller and tore down the TCP reader task, and active callers were disconnected with `Response::Fatal`, masking the deserialization failure as `Error::EndOfStream`. Additionally, `BadPrimitiveValue(Box<dyn Error>)` prevented `DeserializerError` from being `Send + Sync + Clone`. This was resolved by wrapping `BadPrimitiveValue` errors in `Arc<dyn Error + Send + Sync>`, deriving `Clone` on `DeserializerError`, adding `Error::Deserialize(DeserializerError)` with `From<DeserializerError> for Error`, storing `Result<..., DeserializerError>` inside `OneShotCall` and `ArrayListCall`, having `event_loop` log a warning and continue without breaking on `CallError::BadSentence`, and surfacing `Error::Deserialize` to the failing caller upon `!done`.

### 14. [RESOLVED in #26] Panics on Socket Write Errors and Infinite Hang When Event Loop Has Exited (`src/api/mod.rs` & `src/api/listener.rs`)
Previously, `do_call` called `.unwrap()` directly on `send_command(...).await`, causing panics on broken pipes or socket write failures instead of returning `Err(Error::Io(_))`, and leaving allocated tags orphaned in `tag_map`. Additionally, if `event_loop` had already exited (due to EOF or read error), `do_call` inserted a new tag into the vacated `HashMap` and returned a caller future that hung forever. This was resolved by introducing a `TagMap` struct containing a synchronized `closed: bool` flag and `close()` method invoked by `event_loop` on exit, making `do_call` fallible (`Result<Box<T>, Error>`), rejecting new calls with `Err(Error::EndOfStream)` when `is_closed() == true`, cleaning up allocated tags on `send_command` failure before returning `Err(Error::Io(_))`, and properly handling `do_call` errors across all API methods (`authenticate`, `system_resources`, `interfaces`, `generic_oneshot_call`, `generic_array_call`, `generic_streaming_call`, and `cancel`).

### 15. [RESOLVED in #27] `generic_oneshot_call::<()>` Fails on Write Commands, Dropped `!done` Attributes (`=ret`), and Ignored `!trap` After `!re`
Previously, `OneShotCall::done` unconditionally set `call.inner = Some(Ok(Response::Done))`, which converted into `Err(Error::EmptyResponse)` via `From<Response<T>> for Result<T, Error>`. This caused `generic_oneshot_call::<()>` to fail with `EmptyResponse` on write/action commands (`/system/identity/set`, `/interface/enable`, etc.) that only return `!done`. Additionally, `event_loop` called `caller.done()` without passing the `sentence` vector, dropping attributes like `=ret=...` returned by `add` or `count-only` commands. Furthermore, `OneShotCall::push_reply` ignored incoming `!trap` error frames if a `!re` frame was already received. This was resolved by passing `sentence: Vec<String>` to `AsyncCall::done`, implementing `deserialize_done_payload::<T>`, prioritizing `Response::Trap` over `Reply` in `OneShotCall::push_reply` (and allowing `Trap` to overwrite `Some(Err(_))` in `ArrayListCall::push_reply`), deserializing `()` or `ret` attributes directly from `!done`, preserving `EmptyResponse` for non-unit types on bare `!done`, surfacing `Error::Deserialize` if `!done` attributes fail to parse, and preserving `Response::Done` in `MikrotikAPI::cancel`.

### 16. [RESOLVED in #28] Memory Leak on Dropped `StreamingCall` and EOF Masking as `Done`
Previously, `StreamingCall` stored both Tokio `UnboundedSender` and `UnboundedReceiver` inside a shared `Arc<Mutex<InnerStreamingCall>>`. When a consumer stream was dropped without calling `/cancel`, the receiver was never dropped because `TagMap` held the producer handle, causing incoming replies to accumulate in memory without bound and leaking the tag. Additionally, `StreamingCall::disconnect()` sent `Response::Done`, causing consumers to see a normal stream termination instead of detecting socket errors or unexpected EOF. This was resolved by decoupling producer and consumer so `StreamingCall` owns `Option<UnboundedReceiver>` directly (with `Clone` setting `receiver: None` for `TagMap`), checking `is_closed()` before deserializing in `push_reply`, having `event_loop` remove the tag from `TagMap` upon `CallError::ChannelClosed` without breaking the loop, and having `disconnect()` emit `Response::Fatal` followed by `Response::Done`.

### 17. [RESOLVED in #42] Misformatted `.id` and `.proplist` Attributes and Duplicate `.tag` in `send_command` / `do_call` (`src/api/mod.rs`)
Previously, `send_command` formatted any attribute starting with `.` as `{}={}` instead of `={}={}`, causing parameter attributes like `.id` and `.proplist` to be transmitted without a leading `=` (`.id=*1`, `.proplist=name`). In the RouterOS API protocol, `.tag` is the only control word sent without a leading `=`; attributes like `.id` and `.proplist` are command parameters and require a leading `=` (`=.id=*1`, `=\.proplist=name`). This caused property filtering to be ignored and commands targeting item IDs to fail. Additionally, `do_call` unconditionally prepended `.tag` at index 0 without checking if callers supplied `.tag` or `=.tag`, generating duplicate tags. This was resolved by specifically matching `.tag` for raw formatting, retaining caller-provided `=...` prefixes, prefixing all other attributes (including `.id` and `.proplist`) with `=`, filtering user-supplied `.tag`/`=.tag` in `do_call`, and removing the workaround in `mk-client`.

### 18. [RESOLVED in #50 (part of #43)] `OneShotCall::done` Fabricating `Ok(T)` on Bare `!done` for Maps and All-Optional Structs (`src/api/de/mod.rs` & `src/api/call/one_shot.rs`)
Previously, `deserialize_done_payload` passed the trailing empty sentence terminator `""` of a bare `!done` sentence (`["!done", ".tag=1", ""]`) into `SentenceDeserializer`. When `T` was a map (`HashMap<String, String>`, `BTreeMap`) or a struct whose fields were all `Option<T>` or `#[serde(default)]`, `StructVisitor::next_key_seed` read `""` on the first key and returned `Ok(None)`, causing Serde to construct an empty/default `T` and `OneShotCall::done` to return `Ok(Response::Reply(T::default()))` instead of `Response::Done` (`Err(Error::EmptyResponse)`). This was resolved by introducing `has_done_attributes`, passing an empty word iterator to `SentenceDeserializer` in `deserialize_done_payload` when a `!done` sentence has no data attributes (so only unit types succeed and maps/structs fail with `MissingWord` and resolve to `Response::Done`), and guarding top-level `deserialize_option` on an empty cursor.

### 19. [RESOLVED in #51 (part of #43)] `OneShotCall::disconnect` Returning Stale `Reply` on Mid-Call Disconnect / EOF (`src/api/call/one_shot.rs`)
Previously, `OneShotCall::disconnect()` only checked `if call.inner.is_none() { call.inner = Some(Ok(Response::Fatal)); }`. If the TCP connection dropped or received `!fatal` after `!re` arrived but before `!done`, `call.inner.is_none()` was `false`, leaving `call.inner` as `Reply(val)` and causing callers to mistakenly treat an interrupted transaction as successful. This was resolved by pattern matching `call.inner` to preserve existing `Response::Trap` router errors while marking all other unfinalized calls (including partial `Reply`) as `Response::Fatal` (`Err(Error::EndOfStream)`).

### 20. [RESOLVED] Dependencies Modernization, Vulnerability Mitigation, and CLI Feature Gating
Direct dependencies were upgraded to modern stable releases, resolving security advisories for `bytes` (CVE-2026-25541 / RUSTSEC-2026-0007), `tokio` (RUSTSEC-2025-0023, RUSTSEC-2026-0386), `time` (CVE-2026-25727 via `simple_logger 5.x`), and `atty` (RUSTSEC-2024-0375). The unmaintained `rustls-pemfile` crate (RUSTSEC-2025-0134) was eliminated by leveraging `rustls_pki_types::pem::PemObject` (`CertificateDer::pem_slice_iter`). Tokio 1.43+ non-blocking socket enforcement for `TcpStream::from_std` was accommodated in unit tests via `client.set_nonblocking(true)`. Furthermore, CLI-specific dependencies (`clap`, `dialoguer`, `simple_logger`, `human_bytes`) were gated behind the optional `cli` feature with `default = ["tls", "cli"]` and `mk-client` marked with `required-features = ["cli"]`, allowing downstream library consumers to avoid compiling CLI dependencies.

### 21. [RESOLVED in #54] Concurrent Request Multiplexing Unlocked via `&self`, Scoped Writer Lock, and `Clone` Support
Previously, public query, listener, and execution methods on `MikrotikAPI<Authenticated>` (`generic_oneshot_call`, `generic_array_call`, `system_resources`, `interfaces`, `cancel`, etc.) took `&mut self` and awaited both request transmission and response collection while holding `&mut self`. This prevented concurrent request batching (`tokio::join!`), forced multi-task applications to wrap `MikrotikAPI` in outer mutexes (serializing calls over the multiplexed transport), and blocked `/cancel` from running while queries were in-flight. This was resolved by moving the connection fields (`output`, `tag_map`, `next_tag`) into an `Arc<MikrotikInner>`, wrapping `output` in a `tokio::sync::Mutex` whose lock is held only during `send_command` byte writes and flushes, changing all API methods on `MikrotikAPI<Authenticated>` to take `&self`, and deriving `Clone` on `MikrotikAPI<S>` (`Disconnected` and `Authenticated`), allowing concurrent requests to interleave and execute out-of-order over the underlying full-duplex connection.

## 7. Development Guidelines for Agents

1. **Maintain Protocol Conformance**:
   - Ensure all length calculations follow the 1-to-5 byte encoding rule (Section 3.1).
   - Preserve Big-Endian network byte order for length words.
   - Respect sentence delimiter `0x00`.
2. **Preserve Documentation**:
   - Every public API change must include doc comments due to `#![deny(missing_docs)]`.
3. **Follow Idiomatic Rust**:
   - Avoid `unsafe` unless dealing with verified zero-copy string conversions.
   - Use `Result<T, Error>` for fallible operations.
   - Run `cargo fmt` and `cargo clippy --all-targets` before submitting changes.
4. **Testing Protocol Changes**:
   - If adding wire parsing logic, add unit tests in `src/api/read.rs` or dedicated test modules using `std::io::Cursor<&[u8]>`.
